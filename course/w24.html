Concepts and derivation

A report should make the chain from question to evidence explicit. Define the task and data population, explain the objective（目标函数） and architecture, describe selection and evaluation, then show results linked to saved run artifacts. Each table and figure must identify its units and configuration.

Freeze the chosen procedure before final testing. If test feedback changes the model, disclose the reuse and treat the resulting score accordingly. A disappointing result is still a result; hiding it destroys the interpretation of the evaluation.

A five-minute defense should include one worked example, one implementation check and one boundary case. Explain why the method was chosen over a simpler baseline（基线） and what observation would weaken the conclusion. A completed checklist supports auditability but does not certify scientific quality or professional competence.

详细讲解 · 第 1 学习日

A finished report connects a claim to an inspectable chain of evidence

Open the report with the specific question and observed result, including the evaluation scope. Then give enough data and method information to reproduce the comparison. A reader should be able to trace each main number back to a saved run and understand why that run was selected. Screenshots of a notebook are weaker evidence than executable artifacts plus a clear narrative.

Use methods sections to state decisions that affect interpretation: the prediction unit and time, split rule, preprocessing fit boundaries, metric and denominator, tuning budget, checkpoint（检查点） selection and known exclusions. A list of library names is not a method. Explain which information each stage used and which remained unavailable.

Separate observations from explanations. "Validation error increased after adding degree-five polynomial features" is an observation. "The model fit sample-specific variation" is a plausible interpretation that should be supported by training/validation behavior and the protocol. "Polynomial features always hurt" is a general claim not established by that experiment. Good writing preserves these levels.

详细讲解 · 第 1 学习日

Use a final holdout once a selection rule is frozen

Choose the model and threshold using development data, then evaluate the final holdout under the frozen rule. If the result is disappointing, report it. Inspecting final errors can inform future research, but another model chosen from those errors begins a new development cycle. Continuing to call the same set untouched would misrepresent its role.

For a practical tradeoff, suppose model B improves accuracy but doubles latency and uses ten times the memory. There may be no universally best model. State constraints and the decision rule: for example, choose the lowest error among candidates under a 20 ms latency bound measured on specified hardware. Computational measurements need their own protocol, including warmup, batch size and timing scope.

The argument in mathematical notation

Model selection under a stated constraint

\hat m=\arg\min_{m:\,T(m)\le B}\widehat R_{\rm dev}(m)

Select using development risk among candidates meeting a measured resource bound; assess the selected procedure on the final holdout.

详细讲解 · 第 5 学习日

A model answer to the final oral defense

A compact defense might begin: "I predicted a specified outcome for new entities using inputs available at prediction time. I split by entity before fitting preprocessing. A training-mean or majority-class baseline established the reference. I compared one candidate under the same development protocol and selected its settings without final-test access." Replace each generic phrase with your actual task, data and saved artifacts.

Continue with one mechanism: "The penalty changes this objective in this way," or "The convolutional layer shares these local parameters." Then connect a measured result to a limited inference（统计推断）: "On these held-out cases the candidate reduced this loss by this amount; the paired examples show which failures changed." Include actual counts and unexecuted work explicitly.

Close with the strongest limitation and a next experiment that could reduce it. Avoid using a list of familiar terms as a substitute for an explanation. If asked why a source used a different factor, transpose or variance（方差） denominator, reconcile the definitions on paper. That ability demonstrates that the resources have become one usable understanding rather than several memorized summaries.

详细讲解 · 第 2 学习日

Translate a metric table into a bounded recommendation

  1. Candidate A has accuracy 0.84, latency 8 ms and memory 30 MB. B has accuracy 0.86, latency 18 ms and memory 90 MB. C has accuracy 0.87, latency 35 ms and memory 120 MB.
  2. Under an illustrative 20 ms constraint, C is infeasible. Among A and B, B has the highest observed accuracy. This rule selects B, not because it is universally best but because it meets the stated objective and bound.
  3. Under a 10 ms constraint, A is the only feasible candidate. Changing the constraint changes the recommendation without changing the measured accuracy table.
  4. These numbers are constructed arithmetic examples. Your final report must replace them with actual measurements, including uncertainty（不确定性） and hardware context where relevant.
详细讲解 · 第 3 学习日

Package the route from raw data to the main table

Provide an environment specification, configuration, data acquisition instructions or permitted local data, split manifest, training/evaluation commands, saved model state and structured metrics. Include a short command for reproducing the main comparison. Keep secrets and personal data out of shared artifacts; the reproducibility（可复现性） target should state any access restriction. For a local learning project, a clearly documented private dataset can still support an honest restricted reproduction claim.

详细讲解 · 第 3 学习日

Make the illustrative selection rule explicit

candidates = [
    {"name":"A", "accuracy":0.84, "latency_ms":8},
    {"name":"B", "accuracy":0.86, "latency_ms":18},
    {"name":"C", "accuracy":0.87, "latency_ms":35},
]
def select(max_latency):
    feasible = [r for r in candidates if r["latency_ms"] <= max_latency]
    return max(feasible, key=lambda r:r["accuracy"]) if feasible else None

assert select(20)["name"] == "B"
assert select(10)["name"] == "A"
assert select(1) is None
print(select(20), select(10))

详细讲解 · 第 4 学习日

Defend one result, then choose the next learning route

Give a short oral explanation with no slides: the question, the baseline, one mathematical mechanism, one controlled change, one observed result and one limitation. If you cannot explain a denominator, update rule or source convention, return to that specific chapter. A coherent five-minute defense is stronger evidence of understanding than recognizing every term in a large reading list.

Choose the next route from a demonstrated gap. Nonlinear statistical models build on regression, regularization（正则化） and resampling. Probabilistic latent-variable models build on likelihood（似然）, PCA（主成分分析） and clustering（聚类）. Sequence models require reliable tensor shapes and backpropagation（反向传播）. Convex duality（对偶性） requires the linear algebra and optimization foundations. The advanced resource map remains available, but completing this route does not require claiming mastery of every reference book.

The final synthesis is methodological: the Handbook makes operations concrete, ISLP asks whether a statistical comparison is credible, CS229 explains objectives and assumptions, and D2L/PyTorch connect those ideas to trained networks. Use their different viewpoints whenever a result needs a stronger implementation check, interpretation or derivation.

详细讲解 · 第 5 学习日

Further practice with worked solutions

  1. Why can the final test result be worse than the validation result?

    查看逐步解析

    Validation was used for selection and is a finite sample; the final set is another sample and may differ. Check implementation and distribution, but do not silently retune on the final set to make the discrepancy disappear.

  2. What is the difference between a limitation and an excuse?

    查看逐步解析

    A useful limitation identifies a specific boundary of the evidence, its likely consequence and a possible next test. It does not replace reporting the actual outcome or conceal an unexecuted experiment.

Worked example

  1. A defensible claim might be: under this fixed split and budget, variant B had a higher mean validation score, but one of three matched runs was worse.
  2. The report then links the difference table, all configurations and the protocol that produced it.
  3. It separately reports the frozen final-test result, even if that result is less favorable.
  4. A new-process reproduction records the command and discrepancy from the original run. If it was not executed, the report says so.

Comparing the sources

The Handbook contributed a practical data workflow; ISLP provided statistical questions and evaluation; CS229 supplied derivations; D2L and PyTorch connected those ideas to trainable neural systems. The final report uses their strengths together while keeping assumptions and conventions explicit.

The extension index maps remaining textbook topics to prerequisites and a concrete next artifact. Completing this route is not completing every chapter of every source. Choose one extension based on a demonstrated project limitation, rather than collecting more resources without a question.

from pathlib import Path
import argparse

args=parser.parse_args()
required=["README.md","requirements.txt","config.json","report.md"]
if args.project is None:
    print("Audit example. Run with --project PATH to inspect your own project.")
    print("Required files:",required)
else:
    root=args.project.resolve()
    if not root.is_dir():
        raise SystemExit("Project directory does not exist")
    for name in required:
        file=root/name
        if not file.is_file():
            print(name,"MISSING"); continue
        raw=file.read_bytes()
        if name=="config.json":
            json.loads(raw)
        print(name,"sha256:",hashlib.sha256(raw).hexdigest())
    print("File presence is not evidence that results reproduce. Run README commands separately.")

One-page recap

The final skill is not recalling every technique. It is choosing, implementing, evaluating and explaining one method honestly.

replication（复核性重复实验）: A new attempt to investigate a result while documenting which conditions are matched or changed.

limitation（局限）: A boundary on what the design or evidence can establish.

Use the extension routes for nonlinear statistics, survival analysis, EM, convex duality, sequence models or research replication when your next question requires them.
