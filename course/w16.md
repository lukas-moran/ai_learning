# Backpropagation: Local Derivatives and Shared Paths

The forward graph records how a loss depends on parameters. Backpropagation traverses those dependencies in reverse, multiplying along a path and adding contributions from different paths.

## Concepts

For a scalar loss, reverse-mode differentiation propagates a sensitivity for each intermediate value. If a value influences the loss by several routes, the sensitivities add. Reusing a parameter across observations is exactly such a multiple-path case; the batch gradient aggregates all observations.

For scores S=HW2+b2 and mean softmax loss, let G=(P-Y)/n. Then dW2=H-transpose G and db2=sum_rows(G). Propagate dH=G W2-transpose, apply the ReLU mask to obtain dZ1, then compute dW1=X-transpose dZ1 and db1=sum_rows(dZ1). Each derivative must have its parameter shape.

A forward broadcast of a bias creates many uses of one parameter. Its backward operation sums over the broadcast axes. Do not average a second time if G already includes 1/n. Perform gradient checks away from ReLU zero, where a derivative is not uniquely defined.

## Detailed study

## Backpropagation reuses local derivatives on a computation graph

A computation graph（计算图） represents intermediate values and dependencies. Forward evaluation stores the values needed for derivatives. Reverse evaluation starts from the loss and propagates how a change in each intermediate affects that loss. A local derivative answers how a node changes with one parent; the chain rule combines it with the influence already received from downstream. This avoids re-deriving a giant expanded expression for every parameter.

When one value is used by several branches, its total influence is the sum of the contributions from every downstream path. Forgetting this addition is a common shared-parameter bug. The graph also explains why the backward computation usually needs forward values: the derivative of a multiplication depends on the other operand, and the derivative of ReLU depends on its pre-activation sign.

## Derive the matrix gradients from individual entries

For Z=XW+b and an incoming gradient G with the same shape as Z, dW=X-transpose*G because each W[j,k] affects every row Z[i,k] in proportion to X[i,j]. The bias gradient sums G over rows because the same b[k] contributes to each observation. The input gradient is G*W-transpose. Reduction axes follow parameter sharing rather than a memorized transpose pattern.

For mean softmax cross entropy, the output-score gradient is (P-Y)/n under one-hot labels. Through ReLU, multiply incoming derivatives by an indicator that the pre-activation is positive, using a stated convention at zero. Then apply the affine rules layer by layer. The shapes of all parameter gradients must match the corresponding parameters.

## The argument in mathematical notation

### Reverse-mode derivatives of an affine layer

$
Z=XW+\mathbf1b^\top,\quad \nabla_W L=X^\top G,\quad\nabla_X L=GW^\top,\quad\nabla_b L=\sum_iG_{i,:}
$

Here G is the derivative with respect to Z, including any loss averaging. Sum the bias gradient because the bias is shared across rows.

## A directional derivative checks all parameters in one controlled perturbation

Flatten parameters conceptually into theta and choose a direction v of the same shape. For a smooth loss, the derivative of L(theta+t*v) at t=0 equals gradient dot v. Compare that dot product with [L(theta+h*v)-L(theta-h*v)]/(2h). This tests a combination of coordinates with two forward evaluations, making it useful for larger networks.

For L(a,b)=(a*b-4)^2+0.5*(a*b)^2 at (2,3), the gradient is [30,20]. Choose v=[1,-1]. The predicted directional derivative is 10. Perturbing to (2+h,3-h) changes the shared product along both paths, so the finite difference checks the combined effect.

A single direction can accidentally hide compensating coordinate errors. Use more than one direction and retain selected coordinate checks. Pick points away from activation kinks and compare errors over several h values. The goal is independent evidence about the derivative, not a test that reproduces the same algebraic mistake in another function.

## Account for two paths through the same value

1. Let z=a*b and L=(z-4)^2+0.5*z^2. At a=2 and b=3, z=6. The first term contributes 2(z-4)=4 to dL/dz.

2. The second term contributes z=6. Sum the paths to obtain dL/dz=10. Keeping only one term would compute the derivative of a different objective.

3. Since dz/da=b=3 and dz/db=a=2, dL/da=30 and dL/db=20.

4. The forward loss is 4+18=22. A small positive perturbation to a should increase loss by approximately 30 times that perturbation. This sign-and-scale prediction is a useful check before numerical differentiation.

## Use finite differences where the function is smooth

At a ReLU kink, an ordinary derivative does not exist, so a symmetric difference can disagree with a chosen software subgradient convention without proving a bug. Choose test points away from kinks. For smooth points, use float64, several perturbation sizes and both absolute and relative errors. Check multiple coordinates and a random directional derivative. A pass on one zero-gradient parameter is weak evidence.

## Validate accumulation over shared paths

```python
def objective(a, b):
    z = a*b
    return (z-4)**2 + 0.5*z*z

a, b = 2., 3.
z = a*b
dz = 2*(z-4)+z
da, db = dz*b, dz*a
h = 1e-5
numeric_a = (objective(a+h,b)-objective(a-h,b))/(2*h)
numeric_b = (objective(a,b+h)-objective(a,b-h))/(2*h)
assert objective(a,b) == 22
assert da == 30 and db == 20
assert abs(numeric_a-da) < 1e-7
assert abs(numeric_b-db) < 1e-7
print(da, db, numeric_a, numeric_b)
```

## Debug the first incorrect derivative rather than the final accuracy

If the final weight gradient fails, compare the output-score gradient first, then the second-layer weights, then the hidden activation and first layer. This follows the reverse graph and narrows the earliest faulty local rule. Check batch-size scaling by duplicating every observation: a mean loss and its gradient should stay the same, while a summed loss doubles.

D2L's graph-based explanation and CS229's chain-rule derivations describe the same computation at different scales. A library autograd comparison offers a third independent route, provided the forward function, reduction, dtype and parameters are aligned. W17 uses that agreement as a controlled translation exercise.

## Further practice with worked solutions

### Why sum a bias gradient over the batch?

Solution: The same bias affects every row. The derivative of the total loss with respect to that shared parameter accumulates all row contributions, with any averaging already reflected in the incoming gradient.

### Does a finite-difference mismatch at ReLU zero necessarily reveal a code defect?

Solution: No. ReLU is nondifferentiable there. Compare at smooth points and document the chosen derivative convention at the kink.

## Worked example

1. Let a=2, b=3, c=1, u=ab+c=7, and f=u^2=49.
2. The local derivative df/du is 14. Since du/da=b=3, df/da=42.
3. Similarly df/db=28 and df/dc=14. A sign or factor error at one local edge contaminates every upstream derivative.
4. If a also enters a separate term a^2 in the loss, add its derivative 2a=4 to the prior contribution: the total with respect to a becomes 46.

## Comparing the sources

CS229 and D2L derive the same chain rule with different diagram and tensor conventions. MML supplies Jacobians, but implementation rarely needs to materialize a full Jacobian for a scalar loss. Vector-Jacobian products accumulate the needed sensitivities efficiently.

An automatic differentiation framework can validate a manual derivative; it cannot validate that the chosen loss expresses the scientific question. Compare numerical outputs under identical weights, dtype, reduction and activation conventions.

## Implementation

Cache forward values needed by the backward pass. Compute all gradients before mutating any weight.

Check output-layer derivatives first, then hidden-layer derivatives. Use a tiny float64 network and several nonzero pre-activation test points.

Inspect bias gradients explicitly. They often expose incorrect reduction axes or duplicate averaging.

## Controlled experiment

Change one scalar in the computation-graph lab and predict all three derivatives.

Compare analytic and central-difference gradients while varying h. Report both discrepancy and the scale of the true gradient.

Deliberately remove the ReLU mask, observe a failing check, and explain which dependency the incorrect derivative assumed.

## Self-check

1. What happens at a branching path?

Answer: Derivative contributions add.

2. Why sum the bias derivative over rows?

Answer: The same bias was broadcast and used by every sample.

3. Why not update W2 before computing dH?

Answer: dH must use the weights from the same forward computation.

4. Why avoid ReLU zero in a finite-difference check?

Answer: The function is nondifferentiable there; a symmetric difference need not match the chosen software convention.

5. What proves readiness?

Answer: A shape-correct derivation and gradient checks for weights and biases on several tiny cases.

## One-page recap

Backpropagation is dependency accounting. The graph, shapes and reduction convention must agree.

Autograd automates this accounting while leaving training-loop responsibilities to you.

## Terms

- backpropagation (反向传播): Reverse accumulation of derivatives through a computation graph.
- chain rule (链式法则): The derivative rule for composing functions.
- Jacobian (雅可比矩阵): The matrix of partial derivatives of vector outputs with respect to vector inputs.
