Concepts and derivation

A convolutional layer slides a small kernel across an input and reuses its weights at every location. Multiple input channels contribute to each output channel. Weight sharing creates a structural preference for detecting a pattern wherever it appears; it does not make every full classifier exactly translation invariant.

Framework Conv2d normally performs cross-correlation, without reversing the kernel. Mathematical convolution reverses it. Both can learn suitable filters, but a hand calculation must use the same convention as the API.

For input width n, padding p, dilation d, kernel width k and stride s, output width is floor((n+2p-d*(k-1)-1)/s)+1. A dense comparison must account for different parameter counts and inductive assumptions; equal epoch（训练轮次） counts alone are not a fair resource budget.

详细讲解 · 第 1 学习日

A convolutional layer imposes locality and parameter sharing

An image has spatial structure: nearby pixels form patterns, and similar patterns may occur at many positions. A convolutional layer applies one small kernel（卷积核） across positions, sharing its weights. This reduces the number of parameters compared with an unrestricted dense map over all pixels and builds a particular preference into the model. The preference is useful when local repeated patterns matter; it is not universally appropriate for every input representation.

In typical deep-learning libraries, the operation called convolution is cross-correlation（互相关）: the kernel is not spatially flipped. For multiple input channels, each output channel sums local products over all input channels and adds one bias. Parameter count therefore depends on kernel area, input channels and output channels, not directly on image height and width.

Translation equivariance（平移等变性） means shifting an input produces a corresponding shift in an output under compatible boundary and stride conditions. It is different from invariance, which would leave the output unchanged. Pooling and later aggregation can encourage some insensitivity, but padding, stride and image boundaries complicate exact statements.

详细讲解 · 第 1 学习日

Derive output size by counting legal kernel origins

For one spatial dimension of length H, symmetric padding p, kernel size k, dilation d and stride s, the effective kernel width is d*(k-1)+1. The number of valid origins is floor((H+2p-effective_width)/s)+1, assuming the kernel fits. This counts positions rather than memorizing a special case. Apply the same reasoning independently to height and width.

Increasing padding changes boundary assumptions by supplying artificial values. Increasing stride reduces output resolution and can discard fine spatial differences. Dilation changes the spacing of sampled pixels. Before increasing network depth, inspect a single layer's actual footprint and output dimensions.

详细讲解 · 第 1 学习日

The argument in mathematical notation

Count spatial positions and parameters

H_{\rm out}=\left\lfloor\frac{H+2p-d(k-1)-1}{s}\right\rfloor+1,\quad N_{\rm params}=C_{\rm out}(C_{\rm in}k_hk_w+1)

The parameter formula assumes dense channel connectivity and one bias per output channel. Grouped and bias-free layers differ.

详细讲解 · 第 2 学习日

Count a receptive field across more than one layer

With stride-one 3 by 3 kernels and no dilation, the first layer's one output depends on a 3 by 3 input region. A second 3 by 3 layer combines three neighboring first-layer positions along each dimension, so its receptive field（感受野） spans 5 by 5 original pixels. A third such layer spans 7 by 7. The sizes grow through overlapping neighborhoods, not by multiplying 3 by 3 at every layer.

When stride is greater than one, neighboring outputs correspond to more widely separated input positions. Track both receptive-field width and the jump between adjacent output centers. If the current jump is j and the next kernel has width k, receptive-field width increases by (k-1)*j; the next jump multiplies by stride. Dilation modifies the effective kernel width.

A theoretical receptive field identifies possible dependence, not the strength with which every pixel affects an actual prediction. Learned weights and activations can make practical influence uneven. Use the geometric count to frame the architecture, then inspect actual errors and gradients under a defined diagnostic rather than treating the receptive-field size as a performance guarantee.

详细讲解 · 第 2 学习日

Apply a one-dimensional image operator by hand

  1. Use input [1,2,0,3], kernel [1,-1], stride one, no padding and no bias. Cross-correlation produces [1-2,2-0,0-3]=[-1,2,-3].
  2. A mathematically flipped convolution kernel [-1,1] instead produces [1,-2,3]. The operation name matters when matching a formula with a library.
  3. For a 5 by 5 image and a 3 by 3 kernel, stride one, no padding, each spatial output dimension is 3. With one pixel of padding it becomes 5.
  4. For 3 input channels and 8 output channels with a 3 by 3 kernel and biases, parameter count is 8*(3*3*3+1)=224. Reusing those parameters at every position does not increase that count.
详细讲解 · 第 3 学习日

Evaluate in batches without shuffling away alignment between predictions and labels in exported error plots. Save both the configuration and the exact preprocessing used with a checkpoint（检查点）.

Check the kernel convention and parameter count

signal, kernel = [1.,2.,0.,3.], [1.,-1.]
out = [sum(signal[i+j]*kernel[j] for j in range(len(kernel)))
       for i in range(len(signal)-len(kernel)+1)]
assert out == [-1.,2.,-3.]
def output_size(size, kernel_size, stride=1, padding=0, dilation=1):
    effective = dilation*(kernel_size-1)+1
    return (size+2*padding-effective)//stride+1
assert output_size(5,3) == 3
assert output_size(5,3,padding=1) == 5
assert 8*(3*3*3+1) == 224

详细讲解 · 第 5 学习日

Further practice with worked solutions

  1. Why is output-channel count part of parameter count but image width usually is not?

    查看逐步解析

    Each output channel learns one bank of local kernels and a bias, reused at every spatial location. A larger image creates more applications of the same weights.

  2. Does translation equivariance imply the final class prediction never changes after a shift?

    查看逐步解析

    No. Equivariance describes how intermediate outputs shift under specific conditions. Boundary effects, downsampling and later layers can alter the final decision.

Worked example

  1. A 2-by-2 patch [[1,2],[5,6]] and kernel [[1,-1],[1,-1]] give 1-2+5-6=-2 by cross-correlation.
  2. A 4-by-4 input with a 2-by-2 kernel, no padding and stride 1 yields a 3-by-3 output. With stride 2 it yields 2-by-2.
  3. For 3 input channels, 8 output channels and 3-by-3 kernels with bias, parameter count is 8*(3*9+1)=224.
  4. The parameter count does not grow with image width, though activations and computation do.

import argparse
import torch
from torch import nn
from torch.utils.data import DataLoader,Subset,TensorDataset

parser=argparse.ArgumentParser()
parser.add_argument("--mnist",action="store_true")
args=parser.parse_args()
torch.manual_seed(42); torch.set_num_threads(1)
if args.mnist:
    from torchvision.datasets import MNIST
    from torchvision.transforms import ToTensor
    data=MNIST("./daily-data",train=True,download=True,transform=ToTensor())
    order=torch.randperm(len(data),generator=torch.Generator().manual_seed(42)).tolist()
    train=Subset(data,order[:1000]); val=Subset(data,order[1000:1250])
    print("MNIST: fixed train/validation subsets; official test split untouched.")
else:
    # Only verifies shapes and training path. This is not a digit-recognition result.
    X=torch.rand(40,1,28,28); y=torch.arange(40)%10
    train=TensorDataset(X[:30],y[:30]); val=TensorDataset(X[30:],y[30:])
    print("SYNTHETIC SMOKE TEST. Use --mnist for the actual dataset.")
for name in ["MLP","CNN"]:
    torch.manual_seed(42)
    model=(nn.Sequential(nn.Flatten(),nn.Linear(784,32),nn.ReLU(),nn.Linear(32,10))
           if name=="MLP" else nn.Sequential(nn.Conv2d(1,8,3),nn.ReLU(),nn.MaxPool2d(2),nn.Flatten(),nn.Linear(8*13*13,10)))
    opt=torch.optim.SGD(model.parameters(),lr=.1)
    loader=DataLoader(train,batch_size=32,shuffle=True,generator=torch.Generator().manual_seed(42))
    for epoch in range(2):
        model.train()
        for X,y in loader:
            opt.zero_grad(); loss=nn.functional.cross_entropy(model(X),y)
            loss.backward(); opt.step()
    model.eval(); correct=total=0
    with torch.no_grad():
        for X,y in DataLoader(val,batch_size=64):
            correct+=(model(X).argmax(1)==y).sum().item(); total+=len(y)
    print(name,"parameters:",sum(p.numel() for p in model.parameters()),"validation accuracy:",correct/total)

One-page recap

The architecture expresses a hypothesis about spatial structure. Evaluate that hypothesis under the same discipline as a linear baseline.

convolution（卷积）: A local linear filtering operation; deep-learning layers commonly implement cross-correlation.

stride（步幅）: The step between neighboring filter positions.

receptive field（感受野）: The input region that can influence a unit.

padding（填充）: Additional boundary values used before applying a local operation.

Optimization methods change how efficiently parameters move through this larger model.
