The question

Neural-network regularization（正则化） is not limited to adding a penalty. Some techniques change the computation during training, which makes evaluation mode part of the model definition.

Concepts and derivation

In inverted dropout, keep an activation（激活函数） with probability 1-p and divide retained values by 1-p. Its expectation equals the original activation. At evaluation, use the unmasked activation. One finite mask need not preserve the sample mean, and p=1 is outside this formula.

Batch normalization normalizes activations using a mean and variance（方差） over specified axes, then applies learned gamma and beta. Training commonly uses current batch statistics and updates running estimates; evaluation commonly uses those stored estimates. Exact variance estimators and running-update conventions are framework-specific.

Dropout introduces random masking; BatchNorm transforms activations using statistics. They are not substitutes with identical purposes. Tiny batches, shifted deployment data or incorrect mode can make normalization unreliable. eval and no_grad remain separate switches.

详细讲解 · 第 1 学习日

Dropout changes a training-time computation

In inverted dropout（倒置随机失活）, each activation is kept independently with probability q and, when kept, divided by q. For a fixed activation h, the expected dropped-out value is h. At evaluation, the ordinary activation is used. This preserves a first-moment relation at the dropout location; it does not make the expected output of an entire nonlinear network identical to the undropped network.

Dropout introduces noise during optimization and can discourage reliance on particular co-adapted activations. It is a regularization choice whose usefulness depends on architecture, data and training setup. Applying dropout at evaluation makes predictions stochastic and changes the evaluated model. Monte Carlo dropout deliberately uses such stochastic passes under an additional procedure; it should not happen accidentally.

详细讲解 · 第 1 学习日

Batch normalization introduces batch and mode dependence

Batch normalization（批归一化） uses batch-based mean and variance during training and typically running estimates during evaluation, followed by learned scale and offset. Consequently, an observation's training-time output may depend on other observations in its batch. This differs from a fixed preprocessing scaler fitted once on training data. The batch dimensions and framework variance conventions matter.

Calling eval changes this behavior but does not disable gradients. Forgetting evaluation mode can make a validation result depend on batch composition and can update running statistics from validation data. Conversely, training in evaluation mode changes the intended learning algorithm. Mode is part of the state of the experiment and should be tested with a fixed input.

详细讲解 · 第 1 学习日

The argument in mathematical notation

Inverted dropout preserves one mean

\tilde h=\frac{mh}{q},\quad m\sim\operatorname{Bernoulli}(q),\quad E[\tilde h]=h,\quad\operatorname{Var}(\tilde h)=h^2\frac{1-q}{q}

The mask is sampled for a fixed activation in this calculation. Nonlinear downstream expectations do not generally preserve the same relation.

详细讲解 · 第 2 学习日

A tiny batch-normalization example exposes batch dependence

Take a single feature（特征） with training batch values [0,2]. Ignoring epsilon and learned scale/offset, the batch mean is 1 and population variance is 1, giving normalized values [-1,1]. Place the same observation 2 in batch [2,4] and its normalized value becomes -1 rather than 1. Its raw input did not change; its batch context did.

During evaluation, fixed running statistics remove this dependence on the current batch under the usual layer setup. If running mean is 1 and scale is 1, input 2 normalizes to 1 regardless of neighboring evaluation observations. Actual framework training and running-variance estimators can use different conventions, so consult the installed API when reproducing exact values.

This example explains why a validation result that changes with batch composition may reveal a mode bug. It also distinguishes batch normalization from ordinary feature standardization（标准化）, whose training-fit mean and scale are stored preprocessing parameters. Both normalize quantities, but they participate in training and evaluation in different ways.

详细讲解 · 第 2 学习日

Verify what dropout preserves, and what it does not

  1. For h=4 and keep probability q=0.5, inverted dropout returns 8 with probability 0.5 and 0 with probability 0.5. The expected value is 4.
  2. The expected square is 0.5*64=32, while the square of the expected value is 16. Preserving a mean does not preserve every nonlinear transformation.
  3. For h=2, the same procedure returns 4 or 0 with equal probabilities, with mean 2 and variance 4. In general the variance is h^2*(1-q)/q.
  4. At evaluation, the deterministic value h=2 has zero dropout-induced variance. Train-time and evaluation-time outputs are therefore not expected to match on each pass.
详细讲解 · 第 3 学习日

Use a mode check as a targeted behavioral test

Run a fixed batch twice in training mode and twice in evaluation mode. With active dropout, training outputs may differ; deterministic evaluation should agree within the backend's relevant tolerance. Check that validation does not alter model parameters or running statistics. Save a checkpoint（检查点） and compare evaluation predictions after loading it into a reconstructed model. These checks test the intended state transitions rather than only checking file existence.

详细讲解 · 第 3 学习日

Enumerate the two dropout outcomes exactly

h, keep_probability = 4., 0.5
outcomes = [(h/keep_probability, keep_probability),
            (0., 1-keep_probability)]
mean = sum(value*p for value,p in outcomes)
second_moment = sum(value*value*p for value,p in outcomes)
variance = second_moment-mean*mean
assert mean == h
assert second_moment == 32
assert variance == h*h*(1-keep_probability)/keep_probability
assert second_moment != mean*mean
print(mean, second_moment, variance)

详细讲解 · 第 4 学习日

Close project three with error analysis and a bounded claim

Compare the fixed dense or convolutional baseline（基线） with one regularization change at a time. Keep data, split, training budget and checkpoint selection consistent. Inspect whether improvements are concentrated in one class or error pattern. A small gain on a tiny test set may be unstable; record counts as well as percentages and retain multiple-seed results when affordable.

Early stopping（提前停止） selects a training duration using validation. It is another tuning decision, so the final test data must remain separate. The finished report should state which model was selected, why, what was actually run and where it fails. D2L supplies the layer mechanisms; statistical evaluation supplies the limits of what the experiment can establish.

详细讲解 · 第 5 学习日

Further practice with worked solutions

  1. Does E[dropout(h)]=h imply E[f(dropout(h))]=f(h) for every nonlinear f?

    查看逐步解析

    No. The squared example gives 32 versus 16. Expectations do not generally commute with nonlinear functions.

  2. Why can validation in training mode contaminate later evaluation?

    查看逐步解析

    Dropout remains stochastic and batch-normalization modules can use validation batch statistics and update running state. That changes the model or the evaluated computation.

Worked example

  1. For activation x=2 and dropout p=0.5, output is either 0 or 4 with equal probability. Expected output is 2.
  2. A mask on 16 such activations can retain more or fewer than 8, so its observed mean can differ from 2.
  3. For batch [1,3], population mean is 2 and variance is 1. Ignoring epsilon, normalized values are [-1,1].
  4. With gamma=2 and beta=1, outputs are [-1,3]. At evaluation with different running statistics, the same input need not produce these values.

Comparing the sources

D2L develops dropout expectation and BatchNorm mechanics. PyTorch specifies train/eval behavior and running statistics. ISLP and CS229 frame the broader bias, variance and generalization questions that these techniques aim to address.

A normalization layer is not a proof that optimization will improve or overfitting（过拟合） disappear. Compare with the same architecture, data and training budget, and change one technique at a time before testing combinations.

Implementation

Make train and eval mode transitions explicit. Test deterministic evaluation on fixed inputs.

Record dropout probability and BatchNorm configuration. When reloading, restore running buffers as part of state_dict.

Plot training and validation behavior and inspect both underfitting（欠拟合） and overfitting explanations. Do not select epochs using the final test.

import torch
from torch import nn
torch.set_num_threads(1)
torch.manual_seed(42)
X=torch.randn(120,2); y=(X[:,0]+X[:,1]>0).long()
for drop in [0.,.5]:
    torch.manual_seed(7)
    model=nn.Sequential(nn.Linear(2,16),nn.ReLU(),nn.Dropout(drop),nn.Linear(16,2))
    opt=torch.optim.SGD(model.parameters(),lr=.1)
    for _ in range(80):
        model.train(); opt.zero_grad()
        loss=nn.functional.cross_entropy(model(X[:50]),y[:50]); loss.backward(); opt.step()
    model.eval()
    with torch.no_grad():
        acc=(model(X[50:]).argmax(1)==y[50:]).float().mean().item()
        assert torch.allclose(model(X[50:]),model(X[50:]))
    print("dropout/validation accuracy:",drop,acc)
layer=nn.Dropout(.5); ones=torch.ones(12)
layer.train(); print("training:",layer(ones))
layer.eval(); print("evaluation:",layer(ones))

One-page recap

A trained model includes parameters, stored statistics and mode-dependent behavior.

dropout（随机失活）: Randomly masking activations during training under a specified scaling convention.

batch normalization（批量归一化）: Normalization using batch-derived statistics with learned affine（仿射） parameters.

distribution shift（分布偏移）: A difference between the distributions used for training and deployment.

The final project starts with a protocol that makes these choices reviewable before results arrive.
