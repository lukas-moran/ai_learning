# Forward Propagation and Stable Multiclass Loss

A network diagram becomes executable only when every intermediate value has a shape, an axis and an interpretation.

## Concepts

For a row batch X of shape (n,d), choose W1 of shape (d,h), b1 of shape (h,), W2 of shape (h,k), and b2 of shape (k,). Compute Z1=XW1+b1, H=ReLU(Z1), and scores S=HW2+b2. Each row shares parameters but retains its own output.

Softmax normalizes along the class axis for each observation. Subtract the largest score in each row before exponentiating; a common shift cancels between numerator and denominator. This preserves probabilities while avoiding overflow. Summing over the batch axis instead produces the wrong dependency between observations.

For an integer class target y, negative log-likelihood selects -log(p_y). Compute it stably as logsumexp(scores)-score_y rather than taking a logarithm after a probability has underflowed. For mean loss, the score gradient is (P-Y)/n, where Y is a one-hot target matrix.

## Detailed study

## Write a forward pass as a sequence of shape contracts

For a batch of n observations and d features, X has shape (n,d). A hidden layer with h units uses W1 of shape (d,h) and bias b1 of shape (h,). Z1=X*W1+b1 has shape (n,h); activation preserves that shape. An output layer for k classes uses W2 of shape (h,k), giving scores Z2 of shape (n,k). Each row belongs to one observation. Write these roles before translating equations into tensor operators.

A bias is broadcast across rows, not learned separately for each observation. Giving every training observation its own bias can memorize row identities and define a different model. A single-row forward pass is an excellent check of a batch implementation: slicing one observation should produce the same output as the corresponding row of the full forward pass when the model has no batch-dependent behavior.

## Derive stable probabilities from relative scores

Softmax（归一化指数函数） maps scores z_j to exp(z_j)/sum_l exp(z_l). Adding a constant to every score multiplies numerator and denominator by the same factor, leaving probabilities unchanged. Subtracting the largest score ensures every exponent is at most one, which avoids overflow. This is an algebraically equivalent computation with different numerical behavior.

For a true class c, cross entropy is -log p_c. The score-based form is log(sum exp z_j)-z_c. Compute log-sum-exp by extracting the maximum: m+log(sum exp(z_j-m)). A very confident wrong prediction has a large but finite score-based loss even when a separately rounded probability would appear to be zero. Scores need not sum to one or be nonnegative; probabilities do.

## The argument in mathematical notation

### Stable log-sum-exp

$
\operatorname{LSE}(z)=m+\log\sum_j e^{z_j-m},\quad m=\max_j z_j,\quad\ell=\operatorname{LSE}(z)-z_c
$

Subtracting the maximum preserves relative scores while bounding exponentials by one.

## Explain the softmax cross-entropy gradient through competing scores

For one observation and true class c, loss is log-sum-exp(z)-z_c. The derivative of log-sum-exp with respect to z_j is the softmax probability p_j. The second term contributes minus one only for the true class. Thus the score gradient is p_j-1[j=c]. Increasing a wrong class score increases loss, while increasing the true class score decreases it unless its probability is already one.

For probabilities [0.7,0.2,0.1] with the second class true, the gradient is [0.7,-0.8,0.1]. Its entries sum to zero. This matches common-score-shift invariance: moving every score equally should have zero first-order effect. It is a useful algebraic check on a manually coded gradient.

For a mean over n observations, divide each row contribution by n before accumulating shared parameters. A weighted or masked objective changes that normalization. Match the actual loss reduction before comparing gradients with a library; otherwise an apparently correct direction can have the wrong step magnitude.

## Calculate three-class probabilities without large exponentials

1. Let the raw scores be [1002,1001,999] and the true class be the second entry. Direct exponentiation is unnecessary. Subtract 1002 to get [0,-1,-3].

2. Exponentials are approximately [1,0.367879,0.049787], with sum 1.417666. Probabilities are approximately [0.705385,0.259496,0.035119].

3. The cross entropy is log(1.417666)+1, approximately 1.349012. It is not the probability of error; it is a logarithmic score for the probability assigned to the observed class.

4. Subtracting another common constant produces exactly the same mathematical distribution. Changing only one class score changes its relative position and therefore changes probabilities.

## Align label representation and reduction with the loss API

A target can be an integer class index or a vector distribution over classes. The loss API decides which forms it accepts and how they are interpreted. Do not add a softmax before a loss expecting raw logits merely because its name contains cross entropy. Specify whether batch losses are summed, averaged per observation or normalized under weights. Different reductions change the scale of subsequent gradients.

## Stable multiclass probability and loss

```python
from math import exp, log, isclose
def probabilities_and_loss(scores, target):
    maximum = max(scores)
    shifted = [z-maximum for z in scores]
    denominator = sum(exp(z) for z in shifted)
    probabilities = [exp(z)/denominator for z in shifted]
    loss = log(denominator)-shifted[target]
    return probabilities, loss

p, loss = probabilities_and_loss([1002.,1001.,999.], 1)
q, shifted_loss = probabilities_and_loss([2.,1.,-1.], 1)
assert isclose(sum(p), 1.)
assert all(isclose(a,b) for a,b in zip(p,q))
assert isclose(loss, shifted_loss)
print(p, loss)
```

## Use invariances to find bugs that accuracy cannot reveal

Test common-score-shift invariance, row probability sums and batch-versus-single-row consistency. These checks target properties of the function, not a specific implementation. Accuracy may stay unchanged even when probabilities are badly scaled, so an accuracy-only test misses some forward-pass errors. Compare intermediate layer values against a tiny hand calculation before testing on random large arrays.

The mathematical resources often write one observation as a column vector, while code commonly uses row batches. Both can represent the same function. PyTorch stores Linear weights as (out,in), requiring a transpose when copying the course's (in,out) matrix. Keep the shape ledger beside the model comparison.

## Further practice with worked solutions

### Why subtract the largest score instead of the mean score for softmax stability?

Solution: Both shifts preserve exact probabilities, but subtracting the maximum guarantees all shifted scores are nonpositive and their exponentials are at most one.

### A model classifies every example correctly. Must its cross entropy be near zero?

Solution: No. The correct class may only narrowly exceed alternatives. Classification depends on the ordering; cross entropy also measures the probability assigned to the true class.

## Worked example

1. For scores [2,1,-1], subtract 2 to get [0,-1,-3]. Exponentials are approximately [1,0.3679,0.0498].
2. Their sum is about 1.4177, giving probabilities [0.7054,0.2595,0.0351].
3. If the first class is correct, loss is approximately 0.3490. Adding 1000 to every score leaves this result unchanged when computed stably.
4. For a batch of two observations, each row must sum to one independently. A third unrelated observation must not change the first two probabilities.

## Comparing the sources

D2L often uses row-batch equations; some CS229 derivations describe one column-vector observation. Translate by transposing deliberately and write a shape ledger. The underlying function is the same.

PyTorch Linear stores weights as (out_features,in_features) and computes X times weight-transpose plus bias. This course stores W as (in_features,out_features). The difference matters when copying weights for a numerical comparison.

## Implementation

Write forward to return scores and cached intermediates, not only probabilities.

Use max with keepdims along the class axis. Test shift invariance, row sums and a batch of size one.

Keep targets as class indices for indexed loss evaluation. If using a one-hot target for a derivation, state its shape and conversion explicitly.

## Controlled experiment

Use the lab to add a large common shift. Predict why probabilities remain unchanged while naive exp may overflow.

Change hidden width and verify each intermediate shape. Parameter count changes even before any meaningful training comparison.

Duplicate one observation in a batch and confirm its deterministic forward output matches the original.

## Self-check

1. What shape is W2?

Answer: (h,k) in the course row-batch convention.

2. Which axis is normalized?

Answer: The class axis within each sample.

3. Why subtract the row maximum?

Answer: Softmax is shift-invariant, and shifted exponentials are at most one.

4. Must scores sum to one?

Answer: No; probabilities do, scores do not.

5. What should be checked?

Answer: Shape ledger, stable loss, row probability sums and invariance to a common score shift.

## Terms

- forward propagation (前向传播): Computing network outputs from inputs and parameters.
- softmax (归一化指数函数): A mapping from class scores to nonnegative probabilities summing to one.
- log-sum-exp (对数求和指数): A stable building block for normalizing exponential scores.
