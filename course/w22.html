Concepts and derivation

Separate dataset preparation, fitting and evaluation. Learned preprocessing must be stored with the model or reconstructible from training data under the same protocol. Record software versions and randomness sources; a seed alone does not guarantee identical behavior across hardware and library versions.

Aggregate metrics according to their definition. If a loss is averaged within each batch, multiply it by the batch size before summing and divide by total observations. A shorter final batch must not receive the weight of a full batch. Some metrics, including F1（F1 分数）, cannot be correctly aggregated by simply averaging per-batch values.

A model checkpoint（检查点） for inference（统计推断） needs weights, architecture configuration, preprocessing and evaluation behavior. Resuming training may also need optimizer, scheduler and random-generator state. Distinguish functional reproduction from bitwise equality, and choose comparison tolerances for the dtype（数据类型） and computation.

详细讲解 · 第 1 学习日

A baseline implementation should be a complete executable argument

A reproducible baseline has a path from raw inputs to a scored prediction, with each learned transformation fitted on the permitted training data. It is valuable even when its score is weak because it verifies target encoding, row alignment, metric calculation and output format. If a complex model cannot beat it, the baseline helps distinguish a task with little available signal from an implementation or evaluation problem.

For tabular data, preserve column identities through preprocessing. Fit numeric imputation and scaling on training rows, and handle categories with an explicit unknown-category policy. For images, preserve class mapping and the channel/normalization（归一化） convention. A saved model without its preprocessing state is often insufficient to reproduce predictions.

Use a mature library for the full fitted estimator and retain the small hand implementations as instructional checks. The project is not a competition to rewrite every solver. Its engineering goal is a pipeline whose behavior can be inspected and reproduced. That includes failures, excluded rows and configuration, not only the final fitted weights.

详细讲解 · 第 1 学习日

Aggregate losses over the intended statistical unit

A mean loss returned for one batch must be multiplied by the number of observations represented before combining batches into a per-observation average. Otherwise a short last batch receives the same weight as a full batch. With masked sequence tokens, weighted samples or ignored labels, the effective denominator may be something else; use the loss definition rather than assuming it is always batch size.

If the scientific question weights each patient equally, averaging all visits instead answers a visit-weighted question. Aggregate within patient and then across patients when that is the specified estimand（估计目标）. This is the same unit-of-analysis issue from W03, now embedded in evaluation code. A correct formula with the wrong denominator remains a wrong answer to the research question.

详细讲解 · 第 1 学习日

The argument in mathematical notation

Aggregate the numerator before dividing

\bar\ell=\frac{\sum_b n_b\bar\ell_b}{\sum_b n_b}

For a per-observation mean, recover each batch loss sum and its count before combining batches.

详细讲解 · 第 3 学习日

Reproduce preprocessing with a fixed three-row example

Suppose a training feature（特征） is [1,3,missing]. Mean imputation fitted on observed training values uses 2, giving [1,3,2]. A future missing value must also use 2. If a validation table contains [100,missing] and supplies its own mean 100, the transformation has changed between fitting and use.

Feature order is another hidden state. A model with weights [10,1] applied to row [age_scaled,income_scaled]=[2,5] gives 25 before an intercept（截距）. Swapping the columns gives 52. Both are valid dot products with identical shapes. Store names alongside the matrix and assert that the evaluation transform produces the fitted order.

This returns to the shape（形状） contract from W01 but adds semantics. Numerical shape checks cannot detect all errors once tables become arrays. A pipeline should preserve enough metadata to recover which real-world quantity each coordinate represents.

详细讲解 · 第 2 学习日

Combine a short final batch correctly

  1. A first validation batch contains three observations with squared errors [1,1,1], so its mean is 1. A final batch contains one observation with squared error 9, so its mean is 9.
  2. Averaging the two batch means gives 5. Averaging all four observation losses gives (3*1+1*9)/4=3.
  3. Changing validation batch size should not change this per-observation metric for a fixed deterministic model and input set. Use that invariance as a behavioral check.
  4. If outputs depend on batch composition because the model is accidentally in training mode with batch normalization（批量归一化）, fixing only the aggregation code is insufficient. Correct model mode and denominator independently.
详细讲解 · 第 3 学习日

Save enough state to reproduce the measured result

Write configuration and metrics as structured records with run IDs. Save the selected checkpoint and its selection reason. Include preprocessing statistics, feature order, label mapping and software versions. A fresh process should load those artifacts and reproduce fixed-input predictions before rescoring the full dataset. Reproducibility（可复现性） is strongest when the evaluation command consumes the saved artifacts rather than relying on notebook memory.

详细讲解 · 第 3 学习日

Check metric invariance to batch partitioning

losses = [1.,1.,1.,9.]
def aggregate(batches):
    total, count = 0., 0
    for batch in batches:
        batch_mean = sum(batch)/len(batch)
        total += batch_mean*len(batch)
        count += len(batch)
    return total/count

assert aggregate([losses[:3], losses[3:]]) == 3
assert aggregate([losses[:2], losses[2:]]) == 3
assert aggregate([[x] for x in losses]) == 3
wrong = (1+9)/2
assert wrong == 5
print({"correct":3,"unweighted_batch_mean":wrong})

详细讲解 · 第 4 学习日

Audit a saved artifact instead of only the live notebook

Restart the environment, reconstruct the pipeline, load the saved state and run a short fixed-input evaluation. Confirm feature order explicitly: swapping two numeric columns can produce legal computations with wrong predictions. Compare serialized configuration with the experiment protocol. Then run the full baseline and retain actual outputs.

A model card（模型说明卡） can summarize intended use, training data, metric, known failure patterns and restrictions. It complements the executable artifacts. Handbook-style practical code and PyTorch save/load patterns supply mechanics; ISLP's validation framework determines what those artifacts' reported numbers mean.

详细讲解 · 第 5 学习日

Further practice with worked solutions

  1. Why multiply batch mean by batch size before aggregation?

    查看逐步解析

    A mean has already divided the batch loss sum by its count. Multiplication recovers that sum so observations can receive the intended equal weight across differently sized batches.

  2. What can go wrong when weights load successfully but predictions differ?

    查看逐步解析

    Possible causes include preprocessing state, feature order, class mapping, model mode, architecture settings, dtype or backend differences. Loading weights checks only part of the prediction pipeline.

Worked example

  1. Batch one contains four observations with mean loss 1; batch two contains one observation with mean loss 5.
  2. The dataset mean is (4*1+1*5)/5=1.8. The unweighted mean of batch means is 3.
  3. If both batches contain four observations, both formulas give 3. Equality in this special case does not validate the general implementation.
  4. After saving and reloading, compare predictions on fixed examples under the same preprocessing and eval mode. Report a maximum absolute discrepancy and the tolerance used.

Comparing the sources

PyTorch tutorials define the training and save/load interfaces. D2L shows compact loops that must be read carefully for reduction conventions. ISLP defines dataset-level statistical metrics; preserve that definition when implementing batching.

A framework reproducibility note describes limits, not a reason to give up. Record what was controlled and what may vary. The report should say whether a clean rerun was actually executed rather than inferring it from the presence of a checkpoint.

Implementation

Begin with a smoke test that checks one batch, finite loss, a parameter update and reloadable predictions.

Save raw per-example predictions or sufficient counts for final metrics. Weight batch losses by actual sizes.

Run the documented command from a fresh process and verify that hidden notebook state is unnecessary.

Reference program

import tempfile
from pathlib import Path
import torch
from torch import nn
torch.set_num_threads(1)
torch.manual_seed(42)
X=torch.randn(32,2); y=(X[:,0]>0).long()
model=nn.Sequential(nn.Linear(2,8),nn.ReLU(),nn.Linear(8,2))
opt=torch.optim.Adam(model.parameters(),lr=.05)
for _ in range(150):
    model.train(); opt.zero_grad()
    loss=nn.functional.cross_entropy(model(X[:12]),y[:12]); loss.backward(); opt.step()
model.eval()
with torch.no_grad():
    before=model(X)
    print("tiny training accuracy:",(before[:12].argmax(1)==y[:12]).float().mean().item())
    print("validation accuracy:",(before[12:].argmax(1)==y[12:]).float().mean().item())
with tempfile.TemporaryDirectory() as directory:
    file=Path(directory)/"weights.pt"
    torch.save(model.state_dict(),file)
    clone=nn.Sequential(nn.Linear(2,8),nn.ReLU(),nn.Linear(8,2))
    clone.load_state_dict(torch.load(file,weights_only=True))
    clone.eval()
    with torch.no_grad():
        assert torch.allclose(before,clone(X))
print("Save/load equality passed. Repeat this check with the W18 MNIST model.")

Controlled experiment

Change only the final batch size in the lab and predict the difference between the two means.

Reload a checkpoint in a new process and compare fixed predictions. If continuing training, test the additional optimizer state separately.

Keep the failure log when a rerun differs; investigate preprocessing, data order, mode, versions and random state before changing the claim.

Five mastery checks

  1. How is a mean batch loss aggregated?

    查看参考答案

    Weight by actual batch size, sum, then divide by total samples.

  2. Can F1 be averaged across batches?

    查看参考答案

    Not generally; aggregate confusion counts or evaluate all predictions.

  3. Is a seed sufficient for exact reproduction?

    查看参考答案

    No; software, hardware and nondeterministic operations can matter.

  4. Is a checkpoint always enough to resume?

    查看参考答案

    No; optimizer, scheduler and other state may be required.

  5. What is evidence of reproduction?

    查看参考答案

    A fresh-process command, documented inputs and observed output comparison.

One-page recap

Reproduction is an executed procedure with a stated tolerance, not a file checklist alone.

checkpoint（检查点）: Saved state sufficient for a specified restoration or continuation task.

reproducibility（可复现性）: The ability to obtain appropriately consistent results from documented inputs and procedures.

provenance（来源与处理记录）: The traceable history connecting data, configuration, code and outputs.

The results table must preserve uncertainty（不确定性） and inconvenient runs.
